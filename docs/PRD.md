# HKoiKoi.dev MVP PRD

## 🎯 핵심 정보

**목적**: 채용 담당자가 3분 안에 주니어 백엔드 개발자 함상현의 경력·프로젝트·자격을 확인하고 이력서를 받거나 연락할 수 있게 하며, 직접 쓰는 기술 블로그로 전문성을 뒷받침한다.
**사용자**: 채용 담당자·면접관(방문자)과, 모든 콘텐츠를 웹에서 관리하는 본인(관리자 1인).

## 🚶 사용자 여정

```
[방문자]
1. 홈
   ↓ 히어로 CTA / 헤더 메뉴

   [이력서] → 이력서 파일 다운로드 (페이지 이동 없음)
   [연락하기] → 연락
   [대표 프로젝트 카드] → 프로젝트 상세
   [최신 글 카드] → 블로그 상세
   [헤더 메뉴] → 소개 / 프로젝트 목록 / 블로그 목록 / 연락
   ↓

2. 소개 (경력·학력)
   ↓ [자격·어학·논문 보기] → 자격·어학·논문

3. 프로젝트 목록 → 프로젝트 상세
   ↓ [목록으로] → 프로젝트 목록
   ↓ [연락하기] → 연락

4. 블로그 목록 (태그 필터) → 블로그 상세
   ↓ [목록으로] → 블로그 목록

5. 연락
   ↓ 문의 전송 성공 → 완료 메시지 표시(같은 페이지) / 실패 → 오류 표시

[관리자]
6. 관리자 로그인 (푸터 링크로 진입)
   ↓ 허용된 GitHub 계정 인증 성공 → 관리자 대시보드
   ↓ 허용되지 않은 계정 → 로그인 실패 표시

7. 관리자 대시보드
   ↓ [새 글] / 글 선택 → 글 편집
   ↓ [새 프로젝트] / 프로젝트 선택 → 프로젝트 편집
   ↓ 이력서 업로드, 어학 노출 토글 (같은 페이지에서 처리)
   ↓ [로그아웃] → 홈

8. 글 편집 / 프로젝트 편집
   ↓ 저장·발행·삭제 완료 → 관리자 대시보드
```

## ⚡ 기능 명세

### 0. 릴리스 구분

| 릴리스              | 포함 기능                                                         | 포함 페이지                                                           | 완료 기준                    |
| ------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------- |
| **1차 (공개용)**    | F001(최신 글 영역 제외), F002, F003, F004, F005, F008, F009, F015 | 홈, 소개, 프로젝트 목록, 프로젝트 상세, 자격·어학·논문, 연락          | 지원서에 링크를 넣을 수 있음 |
| **2차 (블로그)**    | F006, F007, F010, F011, F001(최신 글 영역 활성화)                 | 블로그 목록, 블로그 상세, 관리자 로그인, 관리자 대시보드(글), 글 편집 | 관리자에서 글 발행 가능      |
| **3차 (관리 편의)** | F012, F013, F014                                                  | 프로젝트 편집, 관리자 대시보드(프로젝트·이력서·공개 설정)             | 배포 없이 주요 콘텐츠 수정   |

- 1차에서는 인증이 없고, 콘텐츠는 시드 데이터로 DB에 입력한다. 이력서는 정적 파일로 제공하고, 어학 노출 여부는 DB 설정값을 직접 바꾼 뒤 재배포해 반영한다.
- 1차 공개 시 헤더의 블로그 메뉴, 푸터의 관리자 링크, 홈의 최신 글 영역은 숨긴다.
- 프로젝트 상세(F004)와 글 상세(F007)는 같은 MDX 렌더러를 쓰므로, 렌더러는 1차에서 만든다.

| **F006** | 블로그 목록·태그 필터 | 발행된 글을 최신순으로 표시하고 태그로 거른다                                               | 전문성을 보여 주는 글 탐색           | 블로그 목록, 홈   |
| **F007** | 블로그 글 상세 (MDX)  | DB에 저장된 MDX 본문을 렌더링하고 코드 블록을 하이라이트                                    | MDX 기반 블로그 요구                 | 블로그 상세       |
| **F008** | 연락 폼 + 이메일 알림 | 문의를 검증·저장하고 본인 이메일로 알림을 보내며 봇 입력을 걸러낸다                         | 채용 담당자와의 직접 접점            | 연락              |
| **F009** | 이력서 다운로드       | 최신 이력서 PDF를 내려받는다(1차는 정적 파일, 3차부터 업로드 파일, 파일이 없으면 버튼 숨김) | 채용 프로세스의 필수 산출물          | 홈, 연락          |
| **F015** | 공통 레이아웃         | 헤더 내비, 모바일 햄버거 메뉴, 푸터, 다크 기본 테마(네이비 + 코랄 포인트)                   | 전 페이지에서 일관된 탐색과 디자인   | 모든 공개 페이지  |

### 2. MVP 필수 지원 기능 (2차·3차)

| ID       | 기능명                | 설명                                                                               | MVP 필수 이유                               | 관련 페이지                    |

### 3. MVP 이후 기능 (제외)

- 경력·학력·자격증·어학·논문·프로필 편집 폼 (MVP는 시드 데이터 입력, 이후 관리자 UI 추가)
- 사회활동(학생회 회계, 교육봉사) 노출
- 문의 내역 관리자 열람 화면 (MVP는 이메일 알림과 DB 저장으로 대체)
- 방문자 댓글, 조회수·좋아요, 검색, 시리즈, RSS
- 영문 지원, 라이트 모드 전환
- 사이트 데이터로 이력서 PDF 자동 생성

## 📝 가정 사항

- **디자인**: 다크 네이비 배경과 코랄(#F26B50 계열) 포인트, 히어로의 원형 링 프로필 사진, `< >` 장식, 기술 스택 띠, 담당 영역 3종, 수치 카운터 구성을 따른다. 참고 이미지의 임의 수치(예: 고객 만족도)는 쓰지 않고 실제 데이터에서 계산한 수치만 노출한다. 모바일에서는 햄버거 메뉴를 쓴다.
- **콘텐츠 저장**: 포트폴리오 콘텐츠도 모두 DB에 둔다. `resume/*.md`를 시드 스크립트로 입력하고, MVP 관리자 UI는 블로그·프로젝트·이력서·어학 노출만 제공한다.
- **개인정보**: 연봉, 자격증 등록번호, 퇴직사유, 고등학교 정보는 데이터 모델에 넣지 않고 사이트에 노출하지 않는다. 이력서 PDF에는 생년월일·주소 같은 불필요한 개인정보를 빼고 올린다.
- **인증 포함 이유**: 본인만 글·프로젝트·이력서를 웹에서 수정해야 하므로 GitHub 로그인 1인 관리자 인증만 포함한다. 방문자 계정·회원가입은 없다. 허용 계정은 변경 가능한 username이 아니라 GitHub 숫자 user id를 환경 변수로 지정한다.
- **연락처**: GitHub와 이메일만 공개한다. 실제 URL·주소는 제공받아야 한다.
- **어학**: TOEIC 620(2026-08-30 취득)은 기본 공개하되 관리자에서 끌 수 있다.
- **MDX 신뢰 범위**: MDX 작성자는 관리자 본인뿐이다. 허용 컴포넌트 목록은 한 파일에 고정하고, import/export와 `{...}` 표현식은 렌더러 설정으로 막는다. MDX는 서버에서 컴파일되므로 관리자 세션 보호가 곧 서버 코드 보호다.
- **MDX 미리보기**: 편집기 미리보기와 문법 오류 표시는 서버 컴파일 결과(렌더러가 반환하는 오류 객체)를 사용한다. 임시저장 글은 글 편집 화면의 미리보기에서만 확인하고, 공개 글 상세는 발행된 글만 조회한다.
- **콘텐츠 공백(제공 필요)**: 프로젝트별 역할·기술·성과와 고객사 공개 가능 범위, 학위 논문 제목·초록·키워드(PDF가 스캔 이미지라 텍스트를 읽지 못함), 주력 기술 스택, 프로필 사진, 도메인(`hkoikoi.dev`) 구매 여부.
- **이메일 발신**: 도메인 확보 전에는 테스트 발신 주소로 본인에게만 알림을 받는 것을 전제로 하며, 도메인 확보 후 인증한다.
- **검증 결과 반영(2026-10-22)**: prd-validator 판정은 조건부 진행이었고, 지적 사항 중 아래 항목을 반영했다. 인증은 Better Auth, MDX 렌더러는 `next-mdx-remote-client` v2로 확정했다.
- **Supabase 일시정지 대응**: 무료 플랜은 7일간 활동이 적으면 일시정지되고 연락 폼 저장도 실패한다. 이를 막기 위해 Vercel Cron(Hobby 플랜 한도 내, 일 1회)이 가벼운 쿼리를 실행한다.
- **1차 콘텐츠 갱신**: 관리자 UI가 없으므로 DB를 직접 고친 뒤 **재배포**해 화면에 반영한다(캐시된 페이지는 재배포 시 초기화됨).
- **2차 블로그 이미지**: Storage 도입(3차) 전에는 외부 URL과 저장소 `public/`의 이미지만 쓴다.
- **이력서 파일 교체(3차)**: 같은 경로에 덮어쓰지 않고 파일명에 버전을 붙여 올린 뒤 `resumeFilePath`를 갱신한다(CDN 캐시 방지).
- **알림 수신 주소**: 도메인 확보 전에는 Resend 가입 이메일과 같은 주소로만 알림을 받을 수 있다.
- **1차 PoC로 확인할 항목**: Shiki 연동과 Vercel 함수 크기, Base UI `Switch`/`Select`와 react-hook-form 연결, GitHub OAuth 콜백 URL의 환경별 처리(2차), `drizzle-kit` 최신 버전.
- **릴리스별 외부 서비스**: 1차는 Supabase(Postgres), Resend, Turnstile, Vercel(Cron 포함)만 쓴다. GitHub OAuth는 2차, Supabase Storage와 이력서 업로드는 3차에 도입한다.
- **릴리스별 데이터 사용**: SiteSetting의 `resumeFilePath`는 3차부터 쓰고, 1차에는 `showLanguageScores`만 쓴다. 프로필 사진은 1차에 정적 파일로 제공한다.
- **원본 자료 보관**: 연봉·등록번호가 있는 원본 이력 자료(`resume/` 원본)는 저장소 밖(`~/Documents/40_Personal/06_Resume/`)에 두고, 저장소에는 정제된 시드 데이터만 둔다.
